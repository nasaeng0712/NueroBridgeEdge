# 실기 확보 후 우선 재개 절차

현재 P1은 BLOCKED다. 아래를 실제 Orange Pi와 SDK 빌드 머신에서 수행하며, 클라우드 CPU 결과로 대체하지 않는다. 장치 인식이나 성공 종료 코드만으로 실제 NPU 추론 PASS를 선언하지 않는다.

## 1. 보유 자원 조사

노트북에서 `python tools/doctor.py`, Orange Pi에서 다음 명령을 실행한다.

```sh
python3 tools/hardware_probe.py --output hardware-inventory.json
```

보고서에는 PCI 장치 ID·드라이버명·커널·아키텍처·BT 어댑터 후보와 도구 유무만 기록한다. 장치 일련번호·인증정보·환경변수는 수집하지 않는다. 보유 키트 장착·정격 전원·저장장치·사용권과 공식 SDK 버전 조합은 별도 확인해야 한다. 부품 구매·유료 서비스·OS 교체는 이 절차에 포함하지 않는다.

## 2. P1 필수 검증

- 현재 설치된 공식 SDK의 버전·펌웨어·드라이버 및 호환성 표를 기록한다.
- 해당 버전의 공식 NPU 데모를 실제 장치에서 10회 실행한다. 입력·출력·종료 코드·device profiler를 회차별 보존한다.
- EEG형 소형 모델의 정적 shape와 연산을 DX-COM에서 검사한다. `reports/model-*/model.onnx`는 **합성 개발 모델**이며 실제 사용자 EEG 모델이 아니다.
- `calibration-training.npy`는 합성 학습 분할 보정 후보로만 사용한다. 실제 SDK의 non-image DataLoader API로 연결하고 설정·로그·산출물 해시를 기록한다.
- 실제 DX-M1에서 10회 추론해 shape/dtype/유한 출력과 실제 NPU 연산 증거를 확인한다. CPU fallback은 요구사항 FAIL이다.
- Bluetooth Classic/SPP 지원과 어댑터·BlueZ 준비성을 확인한다. MindWave 원시 수신은 P2의 별도 실기 검증이다.

현재 코드에는 검증된 DX-COM/DX-RT 바인딩이 없다. 임의 SDK API나 변환 성공을 가정하지 말고 실제 버전에 맞는 공식 예제에서 연결한다. DX-COM 2.5.0/.dxnn v9/DX-RT 3.5+ 조합은 설계도 참고 조합이며 보유 장비 검증 결과가 아니다.

## 3. 이후 보류 항목 순서

P2 실제 Orange Pi 직접 Bluetooth 수신 5분·재연결·원본/재생/해시·저장장애 STOP → P3 FOCUS/VISUAL/MI와 눈/안면 통제 → P4 새 세션 모델 평가 → P5 INT8 정확도 손실·실제 100회 → P6 동기/TTL/장애주입/지연 → P7/P8 신규 독립 평가.

V8-A~C는 사용자 답변에 따라 **후보 유지, 실제 실험 전 별도 확정**이다. 검출력·과제/표본수·교란 통제·판정 규칙을 동결하기 전 목표 합격을 판정하지 않는다. 합성 테스트 완료는 실기 게이트를 해제하지 않는다.

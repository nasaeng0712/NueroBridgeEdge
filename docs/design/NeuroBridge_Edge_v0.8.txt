02. 프로토타입의 의미, 성공 주장과 D02=B 경계
==========================================================================
[확정] 2026년 12월 둘째 주와 2027년 1월 31일의 '목표 성공'에는
실제 사용자 EEG와 DX-M1 INT8 추론, 3D 화면 반응, 독립적인 사용자
의도 판별 증거가 모두 있어야 한다.

LEVEL-0: 합성/공개 EEG 재생 → NPU → 3D. 시스템 통신·연산 시연.
LEVEL-1: 실제 MindWave EEG → NPU → 3D. 의도 판별 근거 미확립.
LEVEL-2: 사전 정한 특정 의도적 과제(집중/중립, 시각 심상/중립,
         좌/우 운동상상 등)를 독립 세션에서 평가해, 우연 수준 및
         실험 교란과 비교한 근거를 확보하고 실시간 제어에 연결.
LEVEL-3: 자유롭게 상상한 구체적인 장면·형태·운동 궤적을 직접 복원.

[이번 결정에 따른 판정]
- 12월 성공 요구 = LEVEL-2 + 실제 DX-M1 INT8 + 화면 제어.
- 1월 성공 요구 = LEVEL-2 + 실제 DX-M1 INT8 + 화면 제어,
  재현성/안정성/성능의 추가 독립 평가.
- LEVEL-0/1은 부분 기술 성취일 뿐 두 목표일의 합격이 아니다.
- LEVEL-2의 '의도'는 미리 지정된 과제 상태의 판별을 뜻하며,
  장면 내용 직접 복원이나 손 움직임 궤적 복원이 아니다.
- LEVEL-2라 하더라도 Fp1 단일 채널의 순수 신경학적 기원은
  안구·얼굴 근육 신호의 완전한 분리 없이 확정할 수 없다.
- 집중/중립 분류 성공이 곧 시각 심상이나 왼/오른손 운동상상
  성공이라고 평가되지는 않는다. 각각 독립 성적을 기록한다.
- 최종 연구 목표 LEVEL-3은 삭제하거나 LEVEL-2로 낮추지 않는다.

[엄격 판정 요구]
- 각 목표일의 평가 데이터는 개발·튜닝 데이터와 분리한다.
- 동일한 EEG 실측 데이터가 NPU에 입력돼야 하고 NPU의 결과가 실제
  렌더 사건으로 연결된 ID 계보를 보존해야 한다.
- 눈 깜박임/시선 전환만으로 유발되는 분류는 의도적 인지 과제의
  독립 판별 성취로 무조건 승격하지 않는다.
- 온라인 실험이 실패했으면 오프라인만 높은 수치로 목표 PASS 불가.

05. ThinkGear SPP 데이터 수집 상세 사양
==========================================================================
[기술 사실 / 공식 통신 규격]
PACKET = 0xAA 0xAA | PLENGTH(1 byte; 0..169) |
         PAYLOAD(PLENGTH bytes) | CHECKSUM(1 byte)
CHECKSUM = (~(sum(PAYLOAD) & 0xff)) & 0xff
DataRow = (0x55 EXCODE)* | CODE | [VLENGTH if CODE>=0x80] | VALUE
- CODE 0x80: RAW 값 길이 2, 16bit signed big-endian.
- CODE 0x02: PoorSignal 값(완전한 무잡음 보증 아님).
- CODE 0x04/0x05: Attention/Meditation 제조사 파생 지표.
- 제품 측정 사양 12bit와 전송 컨테이너 16bit는 서로 다른 개념.

[수신 상태 기계]
DISCONNECTED → DISCOVER → PAIR → CONNECT → STREAMING
→ DEGRADED(손실 의심) → RECONNECTING → STREAMING/FAILED.
프레임 파서 상태:
SCAN_SYNC1 → SCAN_SYNC2 → READ_PLENGTH → READ_PAYLOAD
→ READ_CHECKSUM → PARSE_DATAROW → SCAN_SYNC1.

[필수 단위시험 벡터]
V01 정상 프레임/정상 RAW 양수·음수·0·경계값.
V02 stream chunk가 RAW 2바이트 중간에서 분할됨.
V03 여러 프레임이 한 번에 붙음.
V04 체크섬 틀림·페이로드 길이 초과·미완성 프레임.
V05 미지 DataRow/EXCODE가 존재해도 프레임 안전 처리.
V06 노이즈 바이트 사이 동기 재획득.
V07 `0xAA 0xAA`가 페이로드에 포함됨.
V08 임의 reconnect 후 샘플·프레임 관계가 섞이지 않음.
V09 잘못된 길이·형식에서 인덱스 범위 초과가 발생하지 않음.
V10 저장 실패 시 실시간 분류/이동 명령이 차단됨.

[수신 시간과 연속성]
transport_chunk에 `edge_mono_ns`, `edge_wall_utc`, `offset`, `len` 기록.
seq는 PC/Orange Pi가 부여한 수신 순번이지 MindWave가 제공한
뇌 측정의 전역 샘플 순번이 아니다. 샘플 누락 개수 모르면 null 기록.
재연결·비정상 긴 정지·오버런은 새로운 `segment_id`.
segment 경계를 가로지르는 EEG 윈도우 금지.

06. 저장 형식, 원본 불변성, 데이터 계보 및 복구
==========================================================================
[설계안: Orange Pi 최초 저장]
  data/raw_transport/<session>/partNNN.bin         수신 바이트
  data/raw_transport/<session>/partNNN.index.jsonl 바이트 오프셋/수신 시각
  data/raw_eeg/<session>/partNNN.i16le              파싱된 signed EEG
  data/raw_eeg/<session>/partNNN.index.jsonl       원본 패킷 참조
  data/annotations/<session>/trials.jsonl          지시 과제·시간
  data/processed/<session>/...                      필터/특징
  data/predictions/<session>/results.jsonl         추론 점수/상태
  data/commands/<session>/intent.jsonl             추론→행동
  data/renders/<session>/render.jsonl               실제 화면 동작
  data/reconstructed/<session>/...                  추정값(선택, measured 아님)
  manifests/session.json / manifests/model.json

[필수 ID]
session_id, boot_id, stream_id, segment_id, chunk_seq, packet_offset,
sample_index, trial_id, cue_id, window_id, prediction_id, intent_id,
render_id, model_id, model_sha256, preprocess_sha256.
구간은 [sample_start, sample_stop)로 기록; stop은 포함하지 않는다.
각 파생 결과는 원본 segment와 근거 sample range를 역추적 가능해야 함.

[기록·무결성]
- 수신 바이트는 parsing 이전에 바이너리 원본 스트림에 반영한다.
- 활성 파일은 `.partial`로 쓰고 정상 종료시 flush/fsync 후 닫고 rename.
- 세션별 SHA-256, size, close_state, 오류/재부팅 정보를 기록.
- 파일 인덱스는 실제 오프셋에 대응하는 append-only JSONL.
- raw_eeg는 파싱 성공 샘플만 저장; 오류 패킷은 raw_transport에 남김.
- 수신 완료, 메모리 큐 적재, 파일 write, fsync 완료를 구분해 기록.
- 기기가 보내지 않은 샘플을 AI가 메꾼 경우 별도 reconstructed로만 저장.
- 저장 큐는 유한 크기; 상한 초과 시 조용히 원본 폐기하지 않고
  RECORDING_FAILURE 선언 + 추론 명령 정지.
- 장애 뒤 partial 파일은 회수본으로 표시, 과거 바이트를 임의 수정 금지.
- PC 백업 시 양쪽 SHA-256 일치 확인. USB/네트워크 백업은 별도 경로.
- 외부 클라우드에 원본 업로드하려면 사용자 별도 승인.

[미검증]
저장장치 내구성, 실제 안전 fsync 주기, 디스크 잔여 공간,
실시간 장시간 기록의 실패율. P2에서 검증 후 수치를 동결한다.

07. Fp1 EEG 전처리 및 모델 입력 경계
==========================================================================
[설계안: 모델 기준값은 아직 후보]
- raw_sample_rate: 사양상 512Hz, P2에서 실측 검증.
- window_s=2.0(1024 samples), hop_s=0.25(128 samples).
- PoorSignal / segment integrity / finite / 입력 범위 gate.
- 인과적 SOS IIR 대역 통과 후보, 주파수·계수는 개발 EEG로 결정.
- 50Hz 노치의 유용성은 실제 노이즈 스펙트럼 비교 후 결정.
- 필터 상태는 segment 내 연속 유지. 새 segment에서 초기화/warm-up.
- train/validation/online 동일 파이프라인(미래 샘플 사용 금지).
- 학습 분할에서 계산한 norm_mean/std만 온라인에 적용.
- 특징 파라미터·epsilon·시퀀스·필터 coefficient는 manifest에 기록.

[1차 12-feature 후보 — 채택 미확정]
5개 : theta/alpha/low beta/high beta/전체 유효 대역 log power.
4개 : mean, standard deviation, peak-to-peak, line length.
3개 : zero-crossing rate, Hjorth mobility, spectral entropy.
계산 정의·주파수 경계·eps·정규화는 개발 단계에서 구체 값과
수학적 시험 벡터로 고정해야 함. 이름만으로 같은 feature 구현 보장 안 됨.

[1차 NPU 후보]
input_shape=(1,12) / float32 ABI 입력 후보
Dense(12→16) + ReLU → Dense(16→Nclass).
[미검증] 실제 DX-COM에서 이 텐서 형상과 Gemm 연산이 지원되는지.
대안 shape=(1,12,1,1) Conv1x1 후보는 실기 컴파일 이후 채택.
NPU 내부 양자화(INT8)와 DX-RT 호스트 입력 dtype은 동일하다고 가정 금지.

[품질 AI / EEG 복원 AI]
현재 핵심 경로의 필수 기능이 아님. CPU 규칙 기반 품질 검사 우선.
별도 연구로 제안은 가능하나 원본 보존과 필수 NPU EEG 분류를
대체하는 근거로 사용하지 않는다.

08. 실험 지시, EEG 시간 정합과 라벨 의미
==========================================================================
[과제군]
FOCUS   : 정신 산술 등 집중 과제 vs 중립(첫 우선 시험).
VISUAL  : 지정된 사물/장면 심상 vs 중립(FOCUS와 비교).
MI      : LEFT_MI vs RIGHT_MI 별도 조기 필수 타당성 프로브.
CONTROL : 눈 깜박임, 고의적 시선 전환, 얼굴근육 동작, 지시만/무의도.

[과제 설계]
- 과제 지시는 중앙 고정점, 동일한 자극양식·시각 복잡도 유지.
- 과제 순서를 block 단위 균형·무작위화하여 편향을 줄임.
- 화면에 '왼쪽' 글자와 왼쪽 화살표를 연동하지 않도록 설계.
- 사용자는 실제 손 움직임을 삼가며, 눈/얼굴 움직임은 통제군으로 기록.
- 시각상상 과제를 수행했다는 완전한 내부 정답은 EEG만으로 알 수 없음.

[TRIAL 데이터 계약]
TRIAL_CUE: trial_id, block_id, task_code, pc_cue_requested_ns,
           pc_actual_display_ns, display_frame_id, duration_ms.
TRIAL_ACK: trial_id, edge_receive_ns, session_id, sync_epoch.
과제 구간 시작/끝을 PC 화면에 표시한 실제 타임스탬프로 정의하고,
경계의 불확실 구간은 지정된 guard interval로 제외한다.

[두 장치 시계]
PC/Edge 각각 monotonic clock; wall-time는 사람이 보는 로그만.
SYNC_REQ: t1(PC send) → t2(Edge receive), t3(Edge send)
        → t4(PC receive).
왕복 지연으로 오프셋/불확실성 추정 후 clock_sync_status 기록.
동기 상한을 알 수 없으면 과제 라벨 붙이기와 신선도 판정을 중단한다.
PC cue 표시→PC 렌더 반응은 같은 PC 시계로 계측할 수 있지만,
사용자 뇌 안에서 생각이 실제 발생한 순간→화면 반응 시간과 다르다.

[시행 정보 보존]
trial_id와 sample range/window ID를 직접 연결해 데이터 누출 방지.
서로 겹치는 윈도우 수를 독립 시행 수로 세지 않음.
label은 실험 지시 상태이며 뇌 안의 상상 내용에 대한 절대 정답 아님.

09. AI 학습/검증/독립 최종 시험 프로토콜
==========================================================================
[분리 규칙]
- 사람이 한 과제를 수행하는 trial을 원자적 실험 단위로 정의.
- training / validation / final test는 시행·Run·날짜/세션 기준 분리.
- P3 탐색 결과를 보고 과제·특징·모델을 선택했으면 해당 데이터는
  후속 최종 독립 평가의 새 테스트 데이터로 재사용 금지.
- 양자화 calibration도 training split만 사용.
- 필터/정규화/score 임계값/시간 평활/거부 기준을 validation 이후 동결.
- P7과 P8 평가 시에는 학습에 쓰지 않은 별도 새 세션 사용.
  P7 시험 결과를 보고 모델을 수정하면 P8에서 새 세션 필요.

[선정과제 온라인 평가]
- 온라인 trial 1개는 독립 과제 지시 + 정해진 수행구간 + 결과를 갖는다.
- 정해진 구간 내 valid prediction → 최종 액션을 고정된 집계 규칙으로
  trial-level 명령으로 환산. 다수결/최초 판정/보류 규칙은 시험 전 동결.
- P3/P4 Balanced Accuracy는 시행 단위 confusion matrix에서 산출.
- coverage = 비거부 시행 / 전체 평가 시행.
- 전체 시행 기준 명령 정답률과 coverage 조건부 정확도를 둘 다 제시.
- 중립 상태 오명령률은 신호가 없거나 REST인 구간에서 실제 MOVE 발생
  횟수 / 시간(분). 움직임 총 유지시간도 함께 기록.
- 클래스별 재현율과 FOCUS-VISUAL-MI 각 과제 성능을 별도 보고.
- 순열 검정은 시행/블록 단위 무작위화 제약을 유지하며 수행.
- confidence interval은 시행/세션 구조를 반영해 추정.
- 세션 수가 2개인 파일럿의 '재현성'을 모집단 일반화의 증거로 과장 금지.

[교란 통제]
- 실제 손 움직임, 눈/안구·얼굴 근육, 과제 단서만 있는 시행을 구분.
- 모델이 CONTROL 조건에서 높은 점수를 내는지 오명령률 보고.
- Fp1 한 채널만으로 EOG/EMG와 뇌 신호의 완전한 기원 분리는 불가.
- 근거가 부족하면 D3=A 적용: 원인 분석·재시험 승인 후 P4 진행 보류.

[독립 의도 판별의 문서상 정의]
사용자가 지시된 인지 과제를 선택해 수행한 시험에서,
새 세션 EEG 기반 분류가 사전 기준과 대조 조건을 충족하고,
그 분류 결과가 실제 NPU에서 처리되어 화면에 사용된 사건이 확인됨.
이것은 마음속 장면을 직접 읽었다는 주장을 포함하지 않는다.

10. DX-M1 컴파일, 경량화·양자화 및 실행 계약
==========================================================================
[기술 사실: 최신 공식 문서 검토]
- DEEPX DX-COM v2.5.0이 생성한 .dxnn v9는 DX-RT v3.5.0+ 필요.
- 공식 DX-AllSuite v2.5.0 릴리스의 런타임 모듈 호환 조합을 확인한다.
- 실제 보유 Orange Pi 이미지와 맞지 않으면 최우선으로 현재 설치
  버전을 기록하고 지원되는 통합 조합을 검증한다.
- 소형 EEG 모델의 미지원 연산/정적 입력/양자화 정확도는 미검증.

[개발/배포 절차]
1) 학습용 FP32 기준 모델·데이터 분할·전처리 설정 해시 고정.
2) PyTorch→ONNX 정적 shape export; onnx.checker 수행.
3) 동일 입력으로 FP32 PyTorch↔ONNX Runtime parity.
4) 학습 분할만으로 non-image PyTorch DataLoader calibration 작성.
5) DX-COM 지원 연산·tensor shape·SDK 요구 버전 검토.
6) INT8 컴파일 .dxnn 산출 및 컴파일 요약/파티셔닝 기록.
7) Orange Pi DX-RT에서 모델 load, 실제 DX-M1 infer, profiler 확보.
8) CPU FP32 ↔ NPU INT8 같은 독립 validation 입력으로 정확도 비교.
9) 연산 지연을 input preprocessing / NPU core / host overhead /
   network / renderer로 나눠 기록.

[모델 매니페스트 필수 필드]
model_id, model_sha256, training_dataset_hash, calibration_hash,
architecture, input_names, input_shapes, input_dtypes, feature_order,
class_order, preprocessing_hash, norm_stats, output_dtypes,
onnx_sha256, dxnn_sha256, sdk_runtime_versions, firmware_version,
compiled_op_report, evaluation_protocol_hash.

[성능 요구 충족 조건]
- 실제 사용자 EEG의 특징 또는 구간이 모델 입력이어야 한다.
- `.dxnn`이 로드됐다는 것만으로는 실제 NPU 연산 증거가 아님;
  device profiler·실행로그·입출력 parity를 보존한다.
- CPU만 돌아간 모델은 NPU 필수 요구 FAIL.
- eSense 지표가 3D 움직임을 결정하고 NPU는 더미만 실행했다면 FAIL.
- 정확도 보존과 속도 우위는 서로 별도 지표; 우위는 실측 시에만 주장.

11. Edge↔PC TCP 통신 및 상태 기계
==========================================================================
[네트워크]
- 동일 LAN/유선 Ethernet 우선, TCP 단일 연결.
- Frame = 4-byte uint32 big-endian length + UTF-8 JSON.
- maximum JSON bytes = 16,384. schema_version="1.0".
- 서버/클라이언트 역할: Edge 서버, PC 클라이언트 [설계안].
- session_id / boot_id / sync_epoch / connection_epoch 필수.
- 임의 원본 EEG 전량은 온라인 명령 프레임에 포함시키지 않음.

[메시지 타입]
HELLO, HELLO_ACK, SYNC_REQ, SYNC_RESP, TRIAL_CUE,
TRIAL_ACK, HEARTBEAT, PREDICTION, INTENT, RENDER_ACK, ERROR.

[INTENT 스키마 필수 키]
schema_version, type, session_id, boot_id, stream_id, segment_id,
trial_id, window_id, prediction_id, intent_id, model_id,
model_sha256, input_sample_range, decision_status, action,
score, source_window_end_edge_ns, edge_created_mono_ns,
error_code, command_generation_policy_version.

[입력 검사]
- 길이 초과, 비정상 JSON, 필수 필드 누락, 타입 불일치 → ERROR_SCHEMA.
- session/boot/epoch 불일치 또는 중복 intent_id → 적용 거부.
- Edge가 보낸 score는 float finite, 지원 클래스/액션 enum만 허용.
- 모델 manifest의 클래스 순서와 수신 클래스가 불일치하면 거부.
- 다른 모델·구간의 예측은 해당 실험 trial에 결합하지 않음.
- 링크가 멈추거나 clock uncertainty를 알 수 없으면 STOP.

[Decision 상태]
VALID    = 입력·모델·추론·출력 기준 통과.
REJECT   = 품질/점수/거부 정책상 판단 유보.
INVALID  = 데이터/시계/하드웨어/통신 오류.
CLASS_REST = 학습·검증한 REST 클래스만 사용.
STOP       = 안전 제어를 위한 물리적/렌더 행동(뇌 상태 아님).

[장애·복구]
BT disconnected → STOP; raw append 실패 → STOP + RECORDING_FAILURE.
잘못된 EEG 구간 → REJECT/INVALID; DX-M1 장애 → INVALID+STOP.
TCP 끊김·heartbeat 만료·오래된 응답·새 부팅 ID → STOP.
원본 저장 재개/필터 warmup/새 window/시계 동기 확인 후만 재개.
RAW 기록 큐 초과는 자동 샘플 폐기 금지; failure 기록.
추론 큐는 오래된 window 폐기 가능, 단 반드시 로그 보존.

[지연 및 시간 동기]
PC 표기 시각과 Edge의 mono clock을 그대로 빼서 지연 주장 금지.
NTP형 4-timestamp offset+uncertainty를 사용해 이벤트 나이 상한 계산.
동기 오차/timeout/heartbeat 정량값은 단계 사전 설정값으로 고정.

12. 3D 시각화 엔진과 과제→동작 매핑
==========================================================================
[렌더러 제안] Godot 4.x SceneTree, Node3D 객체, 기본 Mesh/손 에셋.
[확정] 초기는 손 또는 다른 3D 객체가 실제 EEG 분류 결과로 움직임.

[공통 인터페이스]
SceneCommand(scene_id, object_id, action, magnitude, duration_ms,
             source_intent_id, validation_status, render_policy_version).
Action enum: STOP, ROTATE_CW, ROTATE_CCW, MOVE_LEFT, MOVE_RIGHT,
             MOVE_UP, MOVE_DOWN. 유효 enum이 아니면 적용 금지.
RenderEvent(render_id, source_intent_id, pc_applied_mono_ns,
            frame_id, action, actual_object_transform, fps).

[첫 실험 매핑 후보 — 과제 판별 후 활성화]
FOCUS_TASK valid → ROTATE_CW (사전 제작 3D 객체 회전).
실제 학습된 NEUTRAL/REST valid → STOP.
VISUAL_TASK valid → 추가 회전/이동 후보; 판별 검증 전 적용 금지.
LEFT_MI/RIGHT_MI valid → MOVE_LEFT/RIGHT (MI 유의미할 때만).
REJECT/INVALID/timeout → STOP (REST 라벨 생성 금지).

[추적·판정]
- IntentEvent→RenderEvent가 1:1 또는 명시적 처리 정책으로 추적됨.
- 렌더 FPS와 EEG 윈도우 갱신주기 별도로 보고.
- 출력된 손/객체의 사실적 질감과 신경해독 정보량은 별개.
- 다른 3D 객체로 바꿔도 EEG 수집/NPU 모델 코드가 영향받지 않아야 함.
- 기본 무료/로컬 에셋 사용, 유료 자산 필수 의존성 금지.

13. 정량 검증 T-01~T-10 — D01=A 잠정 승인 반영
==========================================================================
[승인 상태 규칙]
아래는 v0.7 §12 숫자를 '잠정 승인된 초기 기준'으로 반영한 것이다.
실험 전 프로토콜/표본수/임계값/수치형 오류 정책과 함께 동결해야 한다.
특히 P8의 일부 성공값은 v0.7 후보에도 없으므로 미승인으로 남는다.

T-01 P1 하드웨어
  - 공식 NPU demo 반복 10회 실제 장치에서 모두 실행.
  - EEG형 대표 12-feature 합성 모델 ONNX→DXNN→DX-M1 10회 유효 출력.
  - NPU/PCIe/SDK 버전과 실제 하드웨어 추론 기록 확인.
  - Bluetooth SPP 경로는 준비성 확인, 실제 헤드셋 수신은 P2.

T-02 P2 수신
  - 파서의 사전 고정 정상/비정상 벡터 100% 기대 결과 일치.
  - 실제 MindWave EEG 연속 5분 수집 및 중단/재연결 사건 기록.
  - 원본 재생시 파싱 결과 동일, 파일 sha256 일치.

T-03 P3 파일럿 규모
  - FOCUS/REST, VISUAL/REST 각각 2개 이상 독립 세션.
  - 세션당 클래스별 최소 20 시행(안내된 조기 파일럿 제안).
  - MI도 별도 2세션·각 클래스/세션 최소 20 시행을 목표로 함.
  - 이 적은 세션은 전체 모집단 일반화를 보장하지 않음.

T-04 P3 계속 연구할 근거(완성 근거 아님)
  - 시행 단위 Balanced Accuracy >= 0.65.
  - 시행/블록 구조 보존 순열 검정 p < 0.05.
  - 각 세션의 점수 우연 수준 초과.
  - 교란 조건에서의 성적 및 오명령을 반드시 보고.
  - 이를 LEVEL-2 최종 성공과 동일시하지 않는다.

T-05 P4 독립 개발 평가
  - 새 검증 세션 Balanced Accuracy >= 0.70.
  - coverage >= 0.70 (거부하지 않은 시행 비율).
  - 95% CI, 클래스별 회상률, 혼동행렬, 교란조건 결과 제출.

T-06 P5 양자화
  - 동일 독립 validation에서 FP32 대비 성능 저하 ≤5%포인트.
  - 실제 DX-M1 반복 추론 100회 오류 0.
  - 실제 NPU 실행/출력 비교/SDK 버전/양자화 manifest 증거.

T-07 P6 응답
  - PC 과제 표시→PC 화면 렌더 적용 p95 ≤3초 후보.
  - Edge NPU 자체 추론 p95 ≤100ms 후보.
  - 두 값은 의도 시작 순간→화면 지연을 뜻하지 않음.

T-08 P6 안전
  - TCP 단절, 낡은 프레임, NPU 오류 각각 10회 주입.
  - 잘못된 MOVE 0회; 초기 timeout 후보 1초.
  - 장애 이후 필터·시간 동기·새 샘플 확보 전 자동 재개 금지.

T-09 P7 화면
  - 유효 명령 이벤트 100건의 mapping 불일치 0건.
  - 렌더링 목표 30fps 후보(실제 장면/GPU의 시험 조건 명시).
  - 실제 EEG→NPU→3D 연결 이벤트 해시·ID 계보 확보.

T-10 P8 온라인
  - 학습·모델 선택에 사용하지 않은 신규 독립 세션 필요.
  - 20분 연속 운용을 초기 후보로 유지.
  - 올바른 과제 명령률, REST/무의도 오명령/분, coverage,
    지연 p50/p95, 교란 조건을 실측하여 제출.
  - [미승인] 온라인 명령 정답률 통과 임계값.
  - [미승인] REST/무의도 오명령률 통과 임계값.
  - [미승인] P7·P8의 통계적 검출력을 만족시키는 최종 시행/세션 수.

[공통 판정 규칙]
- 기능 PASS와 정량 성능 PASS를 별도로 적는다.
- 과제 선택/하이퍼파라미터 조정에 사용한 P3 자료를 최종 테스트로
  재활용하지 않는다.
- P7도 D02=B 때문에 T-04의 탐색 숫자만으로 자동 성공 판정 금지.
  개발 이후 새로운 세션에서 명령 의도에 대한 독립 평가 필수.
- 실제 의도와 상상 내용의 불일치 가능성, EEG 외 잡음 기여를 명시.
- 승인·시험 전에 수치가 확정되지 않은 판정 항목은 HOLD,
  재현된 실측값은 PASS 대용이 아닌 measured result로 보고.

[추가 제안 — 사용자 미승인]
V8-A 온라인 올바른 명령률: 전체 시행 기준 ≥0.70(잠정 후보).
V8-B REST/무의도 MOVE 오명령률: ≤1회/분(잠정 후보).
V8-C P7/P8 신규 평가 규모: 별도 날짜 최소 2세션, 평가 세션마다
     클래스별 최소 30 시행(실험 검출력 검토 전 잠정 후보).
V8-D 시계 동기 상한, cue-edge trial guard, 예측 유효기간,
     신뢰도 거부 임계값은 실제 timing probe 뒤 단위·값 동결.
주의: V8-A~D는 D01=A 승인 대상인 v0.7 후보에는 없던 구체화안이다.
      이를 사용자가 승인하지 않은 상태에서 확정값으로 사용 금지.

P2 MindWave Linux 수신/원본 보존
  목표: 실제 Fp1 EEG를 Orange Pi가 받고 원본·파생데이터 분리.
  자원: 실제 MindWave(별도 구매·수령), BT 어댑터, 원본 저장장치.

  예상 작업: 4~8시간 [가설], 배송 제외.
  산출: raw_transport, raw_eeg, hash manifest, capture_report.

P5 INT8 DX-M1 실제 배포
  목표: 선택 모델을 DX-M1에서 실제 INT8 추론.

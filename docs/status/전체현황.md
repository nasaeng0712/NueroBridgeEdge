이 문서는 단계별 진행 상태의 기준 목록이다. 설계도 원문은 수정하지 않는다.
현재 사용자 지시는 일상적인 단계별 재승인 없이 계속 진행하되, 요구 변경·설계 충돌·필수 검증 실패·중요 미정 결정이 있을 때 중단하는 것이다.

## 현재 중단 사유와 재개 조건

v0.8 §14 순서상 P1 실제 장치 검증이 선행한다. 현재 환경에는 해당 장치의 실행 경로나 사용자 장비 접속 정보가 없다. T-01은 FAIL이 아니라 BLOCKED이며, 합성 CPU 시험으로 대체하지 않는다.

이전 판단 요청은 사용자 A 방식 승인으로 해소되었다. P1 실기 BLOCKED를 유지하면서 장비 없는 준비 구현·합성 검증을 병행한다. 후자를 선택해도 P1/P2 이후 게이트와 최종 성공 판정은 자동 통과하지 않는다.

## 갱신 규칙

기능 단위 완료마다 구현 파일, 실행 명령, 실제 테스트 결과, 커밋, 미검증 항목을 기록한다. PASS/FAIL/BLOCKED/NOT TESTED를 구분한다. 합성·공개 재생·실측 데이터를 구분하며 LEVEL-0/1을 목표 성공으로 보고하지 않는다. 새 단계 착수 전 선행 검증과 중요한 미정 결정을 확인한다.

## A 방식 승인 후: 품질·윈도우 준비 구현

사용자가 P1 실기 BLOCKED를 유지하며 후속 소프트웨어와 합성 테스트를 병행하도록 승인했다. 위의 순서 조정 대기 사유는 해소되었으며 실제 장치 게이트는 계속 보류한다.

- 구현: `neurobridge/windowing.py`, `tests/test_windowing.py`.
- PASS(합성): 전체 17개 테스트. 기본 1024/128 윈도우, 샘플 결손·재연결 경계 분리, 품질 미상/NaN/Inf/범위 초과 시 버퍼 폐기·재준비 확인.
- 개발 정책: PoorSignal=0만 수용하며 미상은 거부한다. 이는 임상 품질이나 신경학적 유효성 보증이 아니다.
- NOT TESTED: M05 SOS 필터, 실측 품질 임계값, 정규화·12-feature 모델 입력. 현재 윈도우는 미필터 원시 입력이며 실기 추론용이 아니다.
- 재현 명령: `python -m unittest discover -s tests -v`.
- 해당 기록과 코드는 동일 기능 커밋으로 저장한다. 커밋 ID는 Git 이력에서 확인한다.

## TCP·안전 수신 준비 구현

- 구현: `protocol.py`(길이 접두 JSON·16,384바이트 제한·중복키/NaN 거부), `safety.py`(식별/모델 고정, 4시각 동기 추정, TTL·heartbeat·동기 만료, 중복·역순 거부, 장애 후 재준비).
- PASS(소프트웨어/합성): 전체 30개 테스트. 실제 루프백 TCP의 분할 수신 검사 포함. BT·저장·NPU·TCP 장애를 합성으로 각각 10회 주입해 신규 동작 차단 확인.
- 중요: 장애 호출은 합성 주입이며 실제 장치 장애가 아니다. `prepare`의 저장/모델/새 샘플 조건은 아직 상위 통합 계층의 보고값이다.
- NOT TESTED: 실제 LAN/Edge·시계 오차, 실측 NPU 오류·통신 단절, Godot 화면 STOP, T-08 실기 전체.
- TTL/heartbeat 1초·동기 오차 상한 20ms·동기 유효기간 5초는 합성 개발 정책이다. 실기 합격 기준으로 승인·동결한 값이 아니다.

## 인과 필터·특징 계산 준비 구현

- 구현: `signal.py`, `requirements-science.txt`, `tests/test_signal.py`.
- PASS(합성): 전체 36개 테스트. SOS 연속/분할 처리 일치, 미래 입력이 과거 출력에 영향 없음, 구간별 상태 초기화, 10Hz 정현파 log power·표준편차 시험, 학습 분할 전용 정규화.
- 특징 순서·대역·epsilon·계수·계산 정의는 전처리 매니페스트와 SHA-256으로 추적한다.
- 개발 기본값은 512Hz, 1~40Hz 4차 Butterworth, 12-feature이다. 이는 설계 후보의 개발 구현이며 실측 데이터로 선택·동결한 모델 입력이 아니다.
- NOT TESTED: 실제 EEG 적합성, 필터 warm-up 기간의 실측 동결, DX-COM 연산/shape 호환, NPU 출력.
- 과학 계산 의존성: 현재 환경 NumPy 2.3.5, SciPy 1.17.0. 과학 경로는 Python 3.11 이상 필요. 기본 진단·파서 경로에는 이 의존성이 불필요하다.

## CPU 합성 통합과 Godot 준비 구현

- 구현: `simulation.py`, Godot `renderer/`, `tests/test_simulation.py`, 한국어 실행 문서와 외부 의존성 출처.
- PASS(합성/소프트웨어): 2048샘플 원본 기록·해시·재생, 9개 특징 윈도우, 실제 루프백 TCP 사전 정의 명령 100건의 안전 수신, Godot 헤드리스 100건의 ID/동작/실제 객체 변환 매핑.
- 첫 Godot 실행은 사용자 디렉터리 쓰기 실패로 종료되었다. 쓰기 가능한 XDG 경로를 지정한 재실행은 종료 코드 0과 보고서 100건으로 확인했다.
- 측정: 첫 성공 Python 실행에서 TCP 수신 p95 42.872ms. 이는 로컬 송수신/프레임 처리 구간이며 NPU·렌더·생각 시작 지연이 아니다. fsync 비용을 포함한 전체 실행 시간·CPU 시간은 로컬 `simulation.json`에 저장한다.
- NOT TESTED: 시각 화면·30fps, 온라인 Godot TCP 제어, EEG로부터의 명령 판별, 실측 장비 경로. Godot 경로는 사전 정의 합성 명령 파일 재생이다.

## 합성 모델·ONNX 준비 구현

- 구현: `training.py`(CPU NumPy MLP 12→16→3, 정적 ONNX export/checker/CPU parity), `evaluation.py`(세션/시행 중복 차단, 시행 confusion/coverage/거부 분리), `requirements-model.txt`, `tests/test_training.py`.
- PASS(합성): 전체 40개 테스트, 스킵 0. 모델 학습·내보내기 실행 약 396ms, FP32 기준↔ONNX 최대 절대오차 약 1.49e-8(현재 클라우드 측정).
- 학습·검증·합성 최종시험 각각 별도 합성 세션 2개, 120시행. 합성 클래스는 6/10/24Hz 정현파이며 사람의 집중/시각상상/MI 라벨이 아니다. 합성 최종시험 BA=1.0은 실제 EEG 성능이나 일반화 근거가 아니다.
- 보정 후보는 학습 분할 특징만 저장한다. 매니페스트에 분할/특징/정규화/모델/ONNX 해시를 기록한다. DXNN·펌웨어는 null이며 실제 INT8·NPU는 NOT TESTED/BLOCKED.
- NOT TESTED: 실제 EEG 학습, 순열 검정·세션 구조 CI·온라인 과제/교란 통제, 실제 INT8/SDK 호환. P3/P4/P5 실기 게이트를 통과한 것이 아니다.

## Godot 실시간 로컬 TCP 및 실기 재개 도구

- 구현: `live_demo.py`, Godot 길이 프레임 수신·상한/명령 검사·1초 합성 watchdog·TCP EOF/손상 시 STOP, `hardware_probe.py`, 실기 재개 문서.
- PASS(소프트웨어/합성): 로컬 TCP로 Godot 100명령 적용과 연결 종료 후 STOP 기록 확인. 첫 실행의 송신→적용 기록 관측 p95 약 7.69ms(헤드리스, 로컬 파일 확인 비용 포함).
- 중요: 장면 API는 Python에서 검증된 합성 명령만 받는다. 이 PC 내부 Scene TCP는 설계의 Edge↔PC 원시 INTENT TCP와 별도다. 실제 Edge의 HELLO/SYNC 서비스·NPU 연결은 아직 미구현이다.
- NOT TESTED: 실측 LAN, 실제 GUI FPS, NPU→Godot 인과 연결, 실제 BT·NPU 장애.
- 사용자 결정 반영: V8-A~C 후보 유지, 검출력·프로토콜 검토 후 실제 시험 전 별도 확정. 최종 성공 임계값으로 자동 적용하지 않는다.

## 합성 CPU 모델 연결·저장 장애 연동 보강

- 구현: 해시·shape·dtype·출처를 확인하는 합성 전용 ONNX CPU 실행기, 선택적인 `simulation --model` 경로, 예측→INTENT→장면 명령 ID 로그.
- CPU 실행기는 NPU fallback이 아니다. 합성 모델만 허용하며 사용자 EEG/실기 모델을 자동 수용하지 않는다.
- PASS(합성): 모델 경로 100명령, 변조된 ONNX 거부, 원본 write 실패가 SafetyReceiver STOP/비활성화로 연결됨. 재생 검증을 스트리밍 방식으로 바꿔 샘플 값과 원본 packet/segment/chunk 참조를 함께 대조한다.
- 합성 재생의 source_window_end_edge_ns는 재생 송출 시각이다. 실제 수집 종료→화면 지연을 측정한 것으로 해석하지 않는다.
- NOT TESTED: 실제 DX-M1 adapter/INT8 compiler. SDK 도구·실물에 접근할 때 공식 API를 확인해 별도 구현해야 한다.

## 최신 전체 검증 요약

현재 클라우드 Python 3.12.14 / NumPy 2.3.5 / SciPy 1.17.0 / ONNX 1.23.2 / ONNX Runtime 1.31.1 / Godot 4.6.3에서 `.venv/bin/python -m unittest discover -s tests -q` 실행: **44개 PASS, FAIL 0, SKIP 0**. 이것은 소프트웨어·합성 입력·가짜 소켓·실제 루프백 TCP·Godot 헤드리스 로직 검증이다. 실제 장비 검증의 PASS는 0건이다. 헤드리스 검증에서 FPS 값은 실제 화면 30fps 판정에 사용하지 않는다.

주요 잔여 구현은 BlueZ 자동 연결 관리, 생산용 저장 회전·장애 복구, 필터 warm-up 실측 정책, 실기 DX-COM/DX-RT adapter, Edge↔PC의 완전한 HELLO/SYNC/ACK 서비스, 과제 큐·독립 온라인 통계/교란 평가다. 현재 여러 준비 모듈이 실행되지만 전체 실기 시스템 완성은 아니다. 장비 확보 시 `docs/실기검증_재개.md`의 P1→P2 검증을 우선한다.
